# 验证与交付

适用于实施交付、回归、排错复验和发布前检查。先确定本次改变的用户结果与受影响路径，选项目规定的必需检查。文案或样式小改检查相关页面；独立功能或缺陷覆盖主路径和相关异常；共用权限、数据或接口补关键允许与拒绝路径及消费者。测试失败不能靠删除有效断言解决。

小任务只留短清单：改变什么用户结果、必需检查/真实目标、有效复用项和何时结束；普通实施做一次，不默认 A/B/C 三套业务副本或多个评测代理。纯解释沿已有短路径；文档与实施仍保留适用必需项，不能因 `smallChange` 全部清空。

执行前先核旧原件与回执：源码、规则、任务、环境、角色/配置、数据和来源身份仍有效且覆盖本次目标，才复用；动态外部状态另核当前事实，不能靠源码 hash 证明。登记在 profile 的检查默认经 `run --profile FILE --check ID` 或 `rules prepare/run/assess --profile FILE --scope <领域>`，复用原回执及同指纹重复保护，不绕过后再补跑一遍。入口受阻确需原命令时，留原因、命令和原始回执；直接命令不冒称受 CE 程序护栏约束。

副本的 stateRoot 与公共记录不同，按 [operations](operations.md) 使用实际安装根的同版本 CLI，并显式传副本 stateRoot；wrapper 固定公共记录不代表 CE runner 不可用。先核现有回执/规则评估再决定是否运行，不能把隔离限制当作重复执行已通过检查的理由。

开发只运行有依据的受影响检查；缺完整影响映射时保留无法排除的必需项，`check.inputs` 是指纹输入而非适用范围，不能据路径不相交跳过。冻结发行候选按原约定全量检查一次；以后只有新修复使相关结果失效时重跑，整体 UI 与真实业务门槛保持。资料包中的范围和完成条件是原检查/验收结果的投影，不是另一套 pass 状态机。

涉及用户操作时进入当前实际入口，以适用角色完成输入、点击、提交、等待，再核对最终业务结果。代码检查、替身接口、模拟数据、只读页面和旧版证据不能替代此步。AI 功能在既有授权及预算内核对真实调用与页面结果。记录足以追溯的版本或环境、入口、角色、操作、预期和实际；高风险变化再补数据范围与调用证据。

扩检只留一行新事实及引用：新变更、新失败、新证据、未知影响，或共享接口/权限/费用/恢复条件变化。失败时先复现并看日志及当前修改；相同失败无新证据时改变调查假设，不盲重试。入口、账号或配置不可用时继续独立工作，并明确标记未验收的部分。代码或环境变化后，旧证据只有适用条件仍相同才能复用。

新界面/交互改变还须对照项目采用的设计决定，结合实际截图、操作与业务结果审查任务路径和视觉层级；脚本通过或已查规范不能关闭待审。设计问题按 [UI 设计回流](ui-design.md) 修相关决定、组件或检查并复测，项目偏好不升格为公共硬规则；没有目标用户试用时不称用户研究通过。

必需检查及真实入口结果均通过，且本次问题处理妥当后停止验证。分别报告实现完成、验证通过与已经发布；发布需符合项目约定，不能由验证通过自动推出。中断时留下当前目标、版本、已完成与未验收项、有效环境及恢复下一步。
