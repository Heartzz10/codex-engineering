# 页面与交互

适用于页面、表单、流程或文案影响用户操作的变化。以项目已有设计、术语和目标设备为准；局部改动保持同类组件与行为一致，不自动重设计整站。

产品方案明确后的新界面、交互或布局，在主要实现前按 [设计方法](../skills/codex-engineering/references/ui-design.md) 先梳理任务、信息与操作，再查相关规范并形成选择；有效旧决定直接复用。交付审查对照项目采用的设计决定，反馈回流同一变更和受影响组件/检查；规范索引不是自动通过凭证。

围绕用户任务排列内容，让当前状态、可做动作、完成结果容易识别。已授权自动完成的步骤不增加无意义确认；涉及必要的业务、费用或数据选择时，说明后果并让用户决策。常用动作应容易发现，文案避免内部实现术语和重复解释。

按受影响流程处理加载、空结果、无权限、输入错误、取消、重试、部分成功与恢复。提交成功只代表操作执行，仍需让用户看到业务结果或下一步。表单要求、错误位置和关键操作后果清楚；优先复用现有表单、表格、筛选、详情及设置组件。

检查目标设备布局、键盘操作、可读性和适用的可访问性。视觉风格随项目和页面用途调整，不强制管理工具、营销页和移动界面采用同一表现。只补真正帮助操作的提示，不为每个标题和控件附加辅助文字。

## 编码前规则与项目适配

UI 实施、交互排错与真实验收时读取本规范，复用当前功能地图、设计变量、控件、状态机制及授权。纯咨询不启动检查；明确局部改动直接提取受影响功能、成功条件、入口和目标，不重复讨论已定目标。

公共目录 `catalog/ui-quality-rules.json` 是 Q01～Q18 分类、官方来源和方法边界的唯一机器原文，版本为 1.0.0。18 类覆盖布局、视觉秩序、文字图标、缩放国际化、语义辅助技术、键盘焦点、指针触摸、输入校验、控件状态、导航退出、异步一致性、业务结果、故障恢复、权限隐私、响应资源、动效媒体、平台衔接及复杂交互。类别不是“能检出所有问题”的18条算法。

先从项目原文形成 `deriveUIQualityConfig(facts)`：每类有适用结论、原因和出处。平台、设计/组件出处、登记检查、场景状态、期望及阈值也由项目事实提供，不从已装依赖猜测。没有该功能才是不适用；有功能但缺驱动/测量是能力缺口；有完整方法但未执行是未验证。事实不足保留 unknown，不能以“没写测试”推定功能不存在。

新 profile 可用 `uiQualityRef` 引用项目内配置；旧 profile 继续可用并显示未配置新增 UI 覆盖。无 UI 明确返回不适用，不启动浏览器。未知平台、规则版本、字段或无出处配置明确报错；当前 Web 能力不关闭原生平台所需的主机、构建、设备和真实操作缺口。

新 Web 控件以适用 WCAG 2.2 A/AA 和 APG 模式作为默认工程依据，保留条款例外和项目更严格标准。原生依对应平台与 WCAG2ICT 适用解释。这里不作全产品合规声明。14px 仅是旧样例约束；间距、命中尺寸、性能等数字须来自适用标准、项目设计或验收成功条件，不设置全局字号、空白率或风格阈值。

## 先检查源码，再运行同一真实场景

源码层复用 profile 已登记的 lint、类型、HTML、控件与状态检查，通过原有 runner 保留授权、指纹、超时和原件。公共 HTML 检查用成熟 html-validate 解析器；不把 JSX 规则强装到 HTML 项目。缺 parser、未知语法、未解析动态模板、未知规则和未登记命令均是缺口，不返回通过。

当前明确启用的 HTML 规则仅为 literal id 重复、正 tabindex、图片显式 alt、输入名称/原生 label 关联、按钮显式 type。每项有错误及合法反例：装饰图空 alt、submit 按钮、0/-1 tabindex、注释与脚本示例均不误报。规则不检查标签含义、排版或真实状态；内嵌禁用指令不能绕过公共检查。其他生态复用项目自己的成熟检查，不新造业务规则。

`prepareUIQuality` 在编码前返回规则、所需场景/方法和能力缺口。编码后先跑登记源码检查，再复用项目受控实例，在真实输入、点击/键盘、等待和业务读回时一次采集布局、语义及状态证据。控件测试或源码通过不能关闭运行/业务要求；只登记源码方法的适用类别明确保留运行缺口。

布局按合法包含、相邻、滚动、层级、命中及项目预期关系判断，不以几何相交直接判遮挡。省略文本须按允许截断及全文访问方式判断；禁用/隐藏须按当前合法状态判断。复杂容器、画布或原生系统无法读取时记录具体边界。动态就绪、字体/图片、超时及失败保留原件，固定睡眠和初始截图不能代表全部状态。

首次界面、结构布局变化、无已核外观基线以及密度/主次/文案疑点保留定向视觉与上下文审查。正常、加载、空、失败、无权限、禁用、部分成功、取消及恢复只验证实际适用状态。异步需核重复提交、乱序/迟到响应、取消与真实副作用；危险操作、收费或外发沿用项目授权与幂等控制。

## 同一验收链中的结果与覆盖

最小观测单元为 `ruleId/categoryId/featureId/acId/entrypointId/targetId/state/platform`，附方法、actual、expected、出处、原件引用和适用版本/角色/环境/数据范围。期望可深比较或有明确来源的 eq/gte/lte/includes/oneOf；不使用生产者自报 pass 代替计算。interaction 需实际操作与等待；business 还须业务 readback。缺 actual、错期望、缺原件、静态冒充业务、初始态冒充错误态和证据漂移不能通过。

`assessUIQualityCoverage` 按同一功能地图计算应检、执行、通过、失败、待判断、缺材料、未执行与不适用。局部验收可限定 AC/目标；完整维护不加局部过滤。发现新入口、适用类别没有需求、缺适配器或过期观测都留缺口。哈希和引用只关联证据；原件有效性、真实账号权限、环境与业务结果继续由项目现有 acceptance 核实，公共汇总不自称业务验收。

上下文审查保留具名 reviewerRef、decisionRef、decision 与原件；无审查决定仍为待判断。例外必须限定现有规则、目标/控件、状态、原因、出处及失效条件，不能全局忽略、覆盖当前失败或把历史问题永久基线化。发现确定错误后按影响修共用根因，在原入口复测并保留有效坏例；不缩字号、隐藏溢出、禁功能/权限、删断言或重拍错误基线换取通过。

## 默认 Codex UI 验收顺序

编码前和源码检查沿用以上入口。随后按“脚本批量检查 → Codex 复核全部报警/待判断/缺口 → 抽查脚本盲区及代表通过页 → 确认错误后修复、同入口复测 → 简短结论”执行。已有脚本实际操作、等待和业务读回可复用；人工复核只加载相关原件，不把所有页面重新完整点一遍。首次页面、布局变化和文案/视觉疑点不能因脚本全绿跳过。

`ui review --file <脚本原件JSON> [--file <更多原件>] --output <项目内相对路径JSON>` 生成精简工作项，终端默认只显示状态、数量、下一步与完整清单路径。原件不改写；输出沿用现有 CLI 不覆盖文件约定。接受已有 `.assessment.json`、带 `layout/rules` 的采集原件、`snapshot/constraints`、`config/observations/context` 及 `captures[].evidence` 批次索引。能取得测量/观测就复用原归约器计算，裸 `pass` 或缺实际/期望值不会产生通过。没有原件的状态返回缺口。

所有 failed、review/needs_review、gap、未执行与缺材料均进入工作项；适配器 `notes` 中 capability_gap 独立保留，不能被运行规则 gap=0 或整页 passed 覆盖。覆盖合同还可由 `context.coverageNotes` 或单项观测的 `coverageNotes` 接入同样的范围。工作项保留规则出处、原件路径/哈希、目标、状态、角色、环境、关键值及下一步；能力缺口和报警数量不是独立产品缺陷数量。

抽查默认按平台、角色、环境、视口取确定代表，另取已有通过页及边界页；`additionalSampleIds` 只增加范围。输出 `sampling.pages/checks/excludedPageIds` 明确抽查页面、已通过目标及未抽查页。核对实际适用的术语与动作主次、错误定位/恢复、权限后果、原生/未取样文字、隐藏状态和其他容器；不能据此声称所有控件、读屏、设备和状态已覆盖。缺口备注指定的目标仍全部逐项处理。

复核后用 `ui review --input <复核清单JSON> --output <新结果JSON>`；输入为 `{reportFiles:[原件路径],reviewFiles:[审查决定文件路径],additionalSampleIds:[可选额外页ID]}`，相对引用从清单目录解析。审查决定文件含 `itemId/reviewerRef/decision/reason/scope/reportRefs/evidenceRefs`；`scope` 必须与工作项一致，`reportRefs/evidenceRefs` 均为 `{path,sha256}`。工具实际读取决定、原件和证据并核哈希；缺 reviewer、出处、证据、目标不符、冲突决定或证据漂移保持待复核。哈希不能证明审查身份或业务真实，具名 Codex 仍须实际查看材料并负责任地判断。

决定取 verified、false_positive、fixed、confirmed_issue、unresolved。报警不能用 verified 直接关闭；confirmed_issue 保持 requires_repair，unresolved 保持待处理。fixed/false_positive 还需 `retestRef:{path,sha256}`，其中包含可重新归约的测量或观测、同规则/入口/目标/状态/角色的实际操作和等待。旧报警/缺口及决定都保留，不能靠生产者自报 pass 关闭。全部有据处理后仅返回 review_complete，始终 `businessAcceptance:false`；业务通过仍由同一项目验收链核对。

普通交付只给简短的实现、验证、发布和未完成范围；长报告按用户要求提供，原件和完整工作项继续保留。本地清单与审查不新增模型 API、付费服务或另一套问题库。

交付分别报告实现、源码检查、实际运行/业务核对、发布和仍缺的平台范围。复用仍有效证据；需要判断的摘要和关键原件按需加载，不常驻巡检、不新建付费视觉服务。UI-W7 原生/专用平台实际链未完成时保留依赖与缺口，不能把公共接口测试或 Web 实证写成全部软件支持。
