# Codex Engineering（CE）

**给 Codex 一套从想法到交付的工作方法。**

CE 是 Codex 的工程协作扩展。你描述想完成的事，CE 帮助 Codex 找到合适的方案、补齐关键需求、完成实现，再通过实际使用确认结果。把选方案的依据、开发的步骤和验收的标准连接起来，让每一步都有来由，也知道什么时候完成。

[直接安装](#开始使用) · [使用指南](START-HERE.md) · [技术架构](ARCHITECTURE.md) · [验证记录](PUBLIC-VALIDATION.md)

## 你可以在这些时候用 CE

### 从想法到方案

- **想法已经有了，关键条件还没说清。** CE 帮助 Codex 补齐使用者、操作场景、成功条件和重要取舍，把一句需求整理成可以实施和验收的目标。
- **准备做新功能，调研依据还没补齐。** CE 引导 Codex 判断哪些未知会改变方案，再查官方资料、公开产品和成熟资源；产品价值未明确时，接入用户、市场与竞品探索。你无需额外写“先调研”。
- **现成方案很多，不确定哪种适合当前项目。** CE 按产品阶段、已有结构、运行环境和维护成本比较。优先复用项目已有、平台原生和合适开源能力，也可借鉴大厂公开做法；本机 demo 选择适合本机的方案。
- **方案写得完整，却偏离了已经确认的目标。** CE 引导 Codex 对照用户决定和项目原文，区分已定事项、建议和未知，保留关键取舍，发现冲突后重评受影响部分。

### 设计、实现与排错

- **页面能画出来，但操作路径和状态反馈还不清楚。** CE 接入交互设计与成熟设计参考，复用项目组件，考虑布局、等待、成功、失败和异常状态，再结合程序检查与整体 UI 审查核对体验。
- **增加一个功能，却容易破坏已有约定。** CE 要求先看现有组件、接口、权限和数据规则，保留用户修改与既有功能，在当前结构中完成必要实现。
- **问题反复出现，修改和重试仍找不到原因。** CE 引导 Codex 先复现、查日志与原件，再选择调查、修复、现场诊断或追踪分析方法。只是核查历史担心时，先确认问题是否存在。

### 验证与交付

- **检查不断增加，已经通过的内容又测一遍。** CE 先定本次必要项和结束条件，核对可复用证据；本地运行器用检查“指纹”和回执识别重复执行。新事实出现时扩大对应范围，必要项完成后结束。
- **程序检查通过了，实际使用仍不确定。** CE 保留整体 UI 审查和真实业务验收：在实际账号、配置与入口中输入、点击、提交、等待，再核对保存、查询等业务结果。
- **需求改了，不清楚会影响哪些已完成功能。** CE 用功能记录关联需求、实现、检查与验收，核对变化和来源。实现完成、验证通过与已经发布分别记录。

### 控制投入，继续已有工作

- **资料和历史越来越多，每次都要重新找上下文。** CE 按当前任务整理必读原件、可选资料、有效决定和待办，按需读取。中断后从保存状态接续，原件变化时重新核对。
- **只是读取文件或改一句文案，也展开完整流程。** CE 为简单读取、明确小改和有效旧决定保留短路径，直接处理受影响部分。
- **多 Agent 配合时，重复工作或文件归属不清。** CE 的协作方法明确职责、上下文、接口与结束条件，由主代理整合；模型建议依据实际支持的档位和任务风险，用户设置继续保留。
- **想控制投入，却分不清 token、调用费和等待。** CE 可从原生记录整理模型用量，业务费用和耗时分别记录，保留失败与重试。经 CE 的供应商实验入口核累计次数与预算，缺失数据保持未知。
- **切换项目后，配置、权限或记录用错了。** CE 通过项目绑定核实际目录、版本、文档和检查入口；项目规则与记录各自保存，本机私有绑定不混入公共包。
- **升级工具时，担心自定义内容和历史丢失。** CE 的升级与回退工具核版本、备份、配置兼容和后续修改；冲突时保留原内容，按记录恢复，项目历史继续保留。

这些方法由 Codex 按任务接入；本地程序负责配置、文件身份、登记检查和记录等确定性核验。[技术架构](ARCHITECTURE.md)列出场景对应的实现与来源，[验证记录](PUBLIC-VALIDATION.md)说明实际测过的范围。

## 开始使用

### 复制这段话，发给 Codex

下面的链接和安装要求已经放在一起。把整段复制到 Codex，即可让它获取文件并完成接入。

```text
请帮我安装 CE：https://github.com/Heartzz10/codex-engineering
先读取仓库的 START-HERE.md，检查 Node.js 22+ 和已有 CE 安装。
首次安装请把仓库获取到本机长期保留的目录，运行 scripts/install-ce.mjs，核对安装后的版本和入口。
已有 CE 时保留自定义规则、运行绑定、项目配置与历史，先备份并检查兼容，再沿原位置处理升级，避免重复安装同名 Skill。
只将运行绑定和记录保存在本机私有目录。完成后告诉我如何在项目中启用 CE。
```

你需要能使用的 Codex 和 Node.js 22 或更新版本；可以让 Codex 检查环境。核心流程无需 Jev 密钥。

### 通过命令行安装

准备好 Git 和 Node.js 22+，在准备长期保留 CE 的位置执行：

```sh
git clone https://github.com/Heartzz10/codex-engineering.git
cd codex-engineering
node scripts/install-ce.mjs
```

安装器核对文件清单、放置 Skill、生成本机私有绑定并验证入口。首次安装使用用户的 `~/.agents/skills`；发现已有 CE 会保留文件，并提示交给 Codex 核对升级。

也可[下载 ZIP](https://github.com/Heartzz10/codex-engineering/archive/refs/heads/main.zip)，解压后把上面的安装请求发给 Codex，说明解压目录即可。

### 在项目里使用

在 Codex 打开你的项目，新建对话，发送：

> 使用 $codex-engineering，给资料库加搜索。沿用已有决定，选择适合当前项目的方案，完成实现和实际验收。

需要时重启 Codex 让新 Skill 显示。完整步骤见[使用指南](START-HERE.md)。

## 技术架构与设计来源

CE 复用 Codex 理解自然语言的能力，通过三部分配合落地：

| 部分 | 做什么 | 带来的作用 |
| --- | --- | --- |
| Skill 与按需方法 | 识别任务，接入需求、调研、设计、排错和验收方法 | 简短请求也能进入合适的工作步骤 |
| 本地工具与规则 | 核配置、运行登记检查、计算指纹、保存回执 | 一部分重复执行与配置错误由程序识别 |
| 项目原件与记录 | 连接决定、实现、验收和剩余待办 | 已有依据可复用，工作可接续 |

CE 借鉴证据优先、按阶段选择方法、按风险验证、按需加载与结果复用等思想。排错接入 Pstack 协议，HTML 和可访问性检查复用 html-validate、axe-core，交互设计按需要参考成熟设计系统与平台指南。

**CE 的设计价值在于把这些方法接到同一条可执行流程：** 自然需求进入、按项目条件选型、模型判断与程序核验配合、证据持续复用、以实际验收和结束条件交付。[技术架构](ARCHITECTURE.md)解释每一部分的实现、来源和适用范围。
