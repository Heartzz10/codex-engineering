# Codex Engineering（CE）

**和 Codex 一起，把想法做到能用。**

CE 是 Codex 的工程协作扩展。你描述想做的事，CE 引导 Codex 补齐关键需求、调查可行方案、复用成熟资源，再完成设计、实现和实际验收。明确的小改直接处理，已经确认的决定继续沿用。

[开始使用](START-HERE.md) · [技术架构](ARCHITECTURE.md) · [验证记录](PUBLIC-VALIDATION.md)

## 从一句需求开始

> 我想给自己的资料库加一个搜索功能。

这样的需求可以直接开始。CE 会引导 Codex 先看现有项目：资料在哪里、怎样搜索才有用、有没有现成能力可以复用。会影响方案的条件还不清楚时，再补充必要调查，比较官方资料、公开组件和接入成本。

一个本机工具可以采用本机方案；正在试想法的产品可以先验证关键链路；已有稳定结构的项目优先沿用现有组件。选型围绕你的目标、运行环境和维护条件展开。

## 在项目中完成什么

| 你要做的事 | CE 如何协助 |
| --- | --- |
| 把想法变成需求 | 整理谁会使用、解决什么问题、成功条件和关键取舍 |
| 决定采用什么方案 | 按需要调查用户、竞品、技术可行性和成熟资源，记录采用理由 |
| 设计页面与交互 | 复用项目组件和设计约定，考虑操作路径、反馈和异常状态 |
| 实现或修复功能 | 保留已有功能与修改，按当前项目结构实施；故障先复现和找原因 |
| 确认真的能用 | 运行受影响检查，在实际入口输入、点击、提交并核对业务结果 |
| 控制验证投入 | 沿用仍有效的证据；扩大检查范围时说明新事实；必要项完成后结束 |
| 继续中断的工作 | 保存原件、决定、完成状态和待办，在下一次任务中接续 |

## 开始使用

准备好 Codex 和 Node.js 22 或更新版本，然后：

1. [下载 CE](https://github.com/Heartzz10/codex-engineering/archive/refs/heads/main.zip)，解压到你准备长期保留的文件夹。
2. 在 Codex 中打开这个文件夹，发送下面这段话。
3. 接入完成后，在你的项目中开启对话，直接描述需求。

> 请读取 START-HERE.md，帮我安装并接入 CE。保留已有配置和项目文件，将运行绑定与记录放在本机私有目录，并检查安装后的入口。

[使用指南](START-HERE.md)包含接入步骤、项目配置和恢复方法。核心流程无需 Jev 密钥；Jev 为可选实验模块，默认关闭。

## 日常直接说需求

> 给资料库加搜索，先看现有能力和成熟方案，再做适合当前项目的实现。

> 我想做一个预约页面，帮我确定关键需求，完成页面和实际操作验收。

> 保存的内容重启后不见了，先复现并查原因，再修复和验证保存结果。

> 把这个按钮改成“保存”，检查受影响页面，完成后结束。

你可以指定采用 CE，也可以直接描述新增功能、方案、性能、设计或故障。Codex 根据 Skill 的说明选择适用方法。

## 工作原理

CE 将三部分连接起来：

- **协作方法**：Skill 帮助 Codex 判断当前需要需求整理、调查、设计、实施还是排错，相关方法按需读取。
- **本地工具**：核对项目配置，运行已登记检查，保存结果，并识别一部分无变化的重复执行。
- **项目记录**：连接需求、实现、验收和待办，让下一次任务可以沿用有效决定与证据。

自然语言和产品取舍由 Codex 结合项目事实判断；配置、文件身份和检查记录由程序核对。页面和业务结果通过实际使用确认。完整说明见[技术架构](ARCHITECTURE.md)。

## 设计来源

CE 采用证据优先、按阶段选择方法、按风险验证、按需加载和复用结果等工程思想。排错接入 Pstack 的四类协议；HTML 与可访问性检查复用 html-validate 和 axe-core。

CE 的特点是把这些方法接到同一条协作流程：从自然需求进入，按项目条件选方案，沿用有效证据，并以实际验收和明确的结束条件完成任务。[架构文档](ARCHITECTURE.md)列出来源、具体采用方式和源码对应。
